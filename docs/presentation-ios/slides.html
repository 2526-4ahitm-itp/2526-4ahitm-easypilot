Die EasyPilot iOS-App

SwiftUI-Companion-App: findet die Drohne im WLAN, zeigt Telemetrie mit 10 Hz, bietet einen 3D-Flugsimulator und sendet Flugbefehle per WebSocket.

SwiftUINetwork.framework SceneKitCoreMotionCombine
Das ist die iOS-Seite von EasyPilot. Die App findet die Drohne selbst im WLAN, streamt Telemetrie mit 10 Hz, hat einen 3D-Flugsimulator und sendet Flugbefehle per WebSocket. Gebaut nur mit Apple-Frameworks, keine Third-Party-Libraries.
Überblick

Wofür wird die App gebraucht?

📡 Verbinden

Automatische Erkennung des ESP32 im WLAN – ohne IP-Eingabe.

📊 Beobachten

Live-Telemetrie: Roll/Pitch/Yaw, Motoren, Akku, Flugmodus, 3D-Modell.

🎛️ Steuern

ARM/DISARM, Balance-, Manual- und Sound-Mode, speicherbare Profile.

🎮 Üben

Simulator mit echter Physik und virtuellen Joysticks – ohne Risiko für die Hardware.

Vier Aufgaben: verbinden, beobachten, steuern, üben. Der Simulator ist wichtig, weil man den Steuerpfad testen kann, ohne dass Propeller drehen.

Motoren

Discovery: iOS hört auf den Beacon, liest die IP und öffnet den WebSocket. Datenpfad: Telemetrie rein, Befehle raus.

Der ESP32 broadcastet alle 5 Sekunden seine IP per UDP. Die App liest sie und verbindet sich auf ws://IP:81. Darüber kommt Telemetrie als JSON mit 10 Hz, Befehle gehen als Text zurück. Der ESP32 spricht per MSP mit dem Flight Controller.

Code · Verbindung

Beacon → WebSocket, auch nach Abbruch

// WebSocketManager.receiveBeacon
if text.hasPrefix("EASYPILOT:") {
    let ip = String(text.dropFirst("EASYPILOT:".count))
        .trimmingCharacters(in: .whitespacesAndNewlines)

    // neue IP ODER verlorene Verbindung zur selben IP
    if !ip.isEmpty && (ip != self.esp32IP || !self.isConnected) {
        DispatchQueue.main.async {
            self.esp32IP = ip
            self.connectWebSocket(to: ip)
        }
    }
}

Der Beacon kommt alle 5 s – das begrenzt automatisch die Reconnect-Versuche. Zusätzlich: Ping alle 5 s, 3 s ohne Telemetrie ⇒ isConnected = false.

Früher blieb die App nach einem Verbindungsabbruch auf OFFLINE hängen, weil der ESP32 dieselbe IP weiter sendet und die App nur bei neuer IP verbunden hat. Die Bedingung "oder nicht verbunden" behebt das.
Code · Befehle

Typisierte Befehle statt JSON-Strings

enum DroneCommand {
    case arm, disarm, stop, safeTest
    case startBalance(baseThrottle: Int, kPRoll: Double, kPPitch: Double)
    case startSound(maxPWM: Int)
    case tiltSound(pwm: Int)
    // … startManual / updateManual

    var payload: String {            // exakt das, was main.cpp parst
        switch self {
        case .arm:  return #"{"cmd":"ARM"}"#
        case let .tiltSound(pwm):
            return #"{"cmd":"TILT_SOUND","pwm":\#(pwm)}"#
        case .safeTest: return "SAFE_TEST"
        // …
        }
    }
}

wsManager.send(.tiltSound(pwm: 1200))
Das Wire-Format steht an genau einer Stelle. Tippfehler in Befehlsnamen sind damit Compile-Fehler statt Laufzeitfehler. Auch FlightMode ist ein Enum, dessen Raw-Values den Firmware-Strings entsprechen.
Code · Threading

Zwei Threads, eine Drohne

Die Physik läuft im SceneKit-Render-Thread, SwiftUI darf nur im Main-Thread aktualisiert werden.

class DroneSimulator: ObservableObject {
    // nur Main-Thread – treibt SwiftUI
    @Published var simRoll: Double = 0
    @Published var isCrashed = false

    // nur Render-Thread – rohe Physik
    var _roll: Double = 0
    var _vel: SIMD3<Float> = .zero

    func tick(dt: Float) { /* Render-Thread: Physik integrieren */ }
    func syncPublished() { simRoll = _roll /* Main-Thread: _vars → @Published */ }
}
Zwei getrennte Zustände: _roll usw. gehören dem Render-Thread, @Published dem Main-Thread. syncPublished kopiert in festem Takt. Keine Locks, keine Race Conditions.
Simulator

Fliegen wie mit echter Hardware

Flugmodi

  • Rate – roh, wie Acro
  • Balance – P-Regler hält die Lage
  • PosHold – hält die Position (GPS-Hold-Gefühl)

Touch-aware Stabilisierung

  • Sticks gehalten ⇒ Lage wird gehalten
  • Sticks losgelassen ⇒ Drohne richtet sich auf
  • Linker Stick los ⇒ Höhenhaltung

Landscape-UI

  • 3D-Szene vollflächig
  • Joysticks als schwebende Corner-Pads
  • Einstellungen als Drawer von rechts

SIM / LIVE

  • LIVE nur bei bestehender Verbindung
  • Stick-Werte als RC-Paket mit 10 Hz
  • Moduswechsel ⇒ DISARM
Sprint 5: Landscape-UI und touch-bewusste Stabilisierung. Loslassen eines Sticks ist eine bewusste Geste wie bei mechanischen Sticks. LIVE sendet die Stick-Werte als RC-Pakete an den ESP32. Der RC-Befehl ist noch ein Format-String in der View und nicht im DroneCommand-Enum.
Sicherheit

Fail-safe an mehreren Stellen

In der App

  • ARM nur per Hold-to-arm (1,5 s)
  • Sound Mode: Neigung > 60° ⇒ Notstopp
  • Safe-Test entprellt (max. alle 2 s)
  • Moduswechsel stoppt laufende Modi

In der Firmware

  • Sound Mode: 1 s ohne Paket ⇒ Motoren aus
  • Heartbeat-Watchdog, Auto-Disarm bei WS-Verlust
  • PWM im Sound Mode auf 1000–1500 begrenzt
Sicherheit liegt in beiden Schichten. Die Firmware darf sich nie darauf verlassen, dass die App richtig reagiert.
