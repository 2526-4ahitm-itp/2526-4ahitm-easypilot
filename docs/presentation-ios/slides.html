EasyPilot

Die iOS-App

4AHITM · HTL Leonding · 2025/26

Ich stelle die iOS-App von EasyPilot vor. Die App ist die Verbindung zwischen dem iPhone und dem ESP32 auf der Drohne.

Was macht die App?

  • findet den ESP32 automatisch im WLAN
  • zeigt Telemetrie an: Lage, Motorwerte, Akku, Flugmodus
  • schickt Befehle: ARM/DISARM, Balance, Manual, Sound Mode
  • hat einen Simulator zum Üben mit virtuellen Joysticks
Der Simulator ist wichtig, weil man die Steuerung testen kann, ohne dass sich Propeller drehen.

Architektur

  iOS-App (SwiftUI)
        │
        │  UDP :4242   "EASYPILOT:<IP>" alle 5 s
        │  WebSocket :81   Telemetrie (JSON, 10 Hz) + Befehle
        ▼
  ESP32-C3 SuperMini
        │
        │  UART, MSP
        ▼
  Betaflight Flight Controller → Motoren
Der ESP32 schickt alle 5 Sekunden seine IP per UDP-Broadcast. Die App liest die IP und verbindet sich per WebSocket auf Port 81. Der ESP32 redet per MSP mit dem Flight Controller.

struct ContentView: View {
    @StateObject private var wsManager = WebSocketManager()

        TabView {

            SimulatorView(wsManager: wsManager)
            ControlView(wsManager: wsManager, motionManager: motionManager)
        }
    }
}
Es gibt nur einen WebSocketManager und einen MotionManager. Beide werden in ContentView erstellt und an die Tabs weitergegeben.

Verbindung zum ESP32

if text.hasPrefix("EASYPILOT:") {
    let ip = String(text.dropFirst("EASYPILOT:".count))
        .trimmingCharacters(in: .whitespacesAndNewlines)

    // neue IP oder Verbindung verloren
    if !ip.isEmpty && (ip != self.esp32IP || !self.isConnected) {
        DispatchQueue.main.async {
            self.esp32IP = ip
            self.connectWebSocket(to: ip)
        }
    }
}
  • Ping alle 5 s, nach 3 s ohne Telemetrie gilt die Verbindung als getrennt
  • vorher ist die App nach einem Abbruch auf OFFLINE hängen geblieben

Befehle

enum DroneCommand {
    case arm, disarm, stop, safeTest
    case startBalance(baseThrottle: Int, kPRoll: Double, kPPitch: Double)
    case startSound(maxPWM: Int)
    case tiltSound(pwm: Int)
    // ...

    var payload: String {
        switch self {
        case .arm: return #"{"cmd":"ARM"}"#
        case let .tiltSound(pwm):
            return #"{"cmd":"TILT_SOUND","pwm":\#(pwm)}"#
        case .safeTest: return "SAFE_TEST"
        // ...
        }
    }
}

wsManager.send(.tiltSound(pwm: 1200))

Simulator

Modi

  • Rate
  • Balance (P-Regler)
  • PosHold

Steuerung

  • Stick halten: Lage bleibt
  • Stick loslassen: Drohne richtet sich auf
  • Landscape: Joysticks in den Ecken
  • LIVE: Stick-Werte gehen als RC an den ESP32

Threading im Simulator

Physik läuft im Render-Thread von SceneKit, SwiftUI darf nur im Main-Thread geändert werden.

class DroneSimulator: ObservableObject {
    // Main-Thread, für SwiftUI
    @Published var simRoll: Double = 0
    @Published var isCrashed = false

    // Render-Thread, Physik
    var _roll: Double = 0
    var _vel: SIMD3<Float> = .zero

    func tick(dt: Float) { /* Physik rechnen */ }
    func syncPublished() { simRoll = _roll /* ... */ }
}

Sicherheit

App

  • ARM nur durch 1,5 s gedrückt halten
  • Sound Mode: über 60° Neigung Notstopp
  • Safe-Test höchstens alle 2 s

ESP32

  • Sound Mode: 1 s kein Paket, Motoren aus
  • Disarm bei Verbindungsverlust
  • PWM im Sound Mode max. 1500
